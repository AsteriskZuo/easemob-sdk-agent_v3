## 3. 工作模式（严格遵守）

1. **spec 闸门（铁律）**：主 agent 写 spec → **用户审过才派发子 agent**。spec 自包含（AGENTS.md #10：执行者只读 spec，每个成员都要有注释），体例统一：`# T<N> <名> spec` + 1 目标 / 2 背景知识（含消费的上游包真实签名）/ 3 范围与不做清单 / 4 包结构 / 5 详细规格 / 6 测试清单 / 7 验收标准 / 8 本规格的决策点。
2. **派发**：子 agent 与主 agent 同模型；并发 ≤2；提示词 = spec 绝对路径 + 工程约定 + 约束（不改 docs/、不动 git、不碰凭据 `.easemob-agent/`、只碰自己目录）+ 验收命令 + 汇报格式；并行时警告 yarn install lockfile 竞争（等 10s 重试 ≤5 次）。
3. **验收**：子 agent 完成后主 agent **独立复验**（根六连全绿 + 抽查源码与 spec 一致）→ 按任务分 commit → 登记进度文档与计划任务表状态。
4. **进度追踪**：任务表状态列是总览；进度文档记明细（状态/子 agent/起止/验收证据/commit/备注）；中断后读这两个文档即可任务级恢复。
5. **工程约定**：yarn 4.14.1（berry，workspaces 纯 `packages/*`+`app/*`）、node≥24、TS ^5.9 ESM NodeNext（相对导入带 `.js` 后缀）、jest29+esbuild（ESM 下 `import { jest } from '@jest/globals'`）、各包 devDeps 自声明、dpdm 循环检查、时间戳 `new Date().toISOString()`、中文注释、workspace 依赖用版本号形式（如 `"@easemob/agent-logger": "0.1.0"`，不用 `workspace:*`）。
6. **依赖管理四类归宿**（AGENTS.md #11 + `design/dependency-rules.md`）：环境变量唯一读口（env 包）/ 全局共享外观（logger，仅初始化后不可变场景）/ 上下文注入工厂 / 纯函数。上下文装配要克制，工具类以类对象为主、无状态纯函数才用方法定义。

## 4. 工作思路（设计判断的依据）

- **AGENTS.md 核心原则**：满足当前需求、短小精悍、低耦合可拆分、少即是稳、避免预测式扩展但保留结构性灵活、独立判断、决策需确认。
- **文档纪律**：骨架 + 子文档；一个内容在一个地方说清楚，其余引用；术语以 glossary 为唯一定义处；写的越多越易歧义——简洁是硬要求。
- **资产模型的核心逻辑**（不要再翻案，除非有真实新需求）：包与工具/skill 的分族依据是**复用性**——包是业务单位通常唯一（复用走 git 本身），工具/skill 是组件复用是常态（故有共享标记）；共享标记不可改是因为"共享改私有"会使已有绑定悬空；asset_id 含属主维度是为了"同三元组不同属主各自管理"；名唯一性靠控制台配置期查重，运行时无优先级无限定写法。
- **平台的定位**：心脏（双循环）只做机械调度、不认识业务细节；业务 = 包 + 配置；平台对子程序的全部要求 = 一入一出四条契约；稳定优先（任何业务错误不影响平台）。
- **单轮审查工单是验收锚点**：所有设计推演都拿它过一遍（webhook 收工单号 → 拉取 → 脱敏 → 大模型审查 → 还原 → 门禁 → 企微通知）。

## 5. 与用户的交互习惯（重要）

1. **先讨论后动手**：凡涉及架构/数据结构/接口/目录/技术路线的选择，先在对话里讨论清楚，用户确认后才改文档；文档审过才实现。讨论期用户常明确说"先不要修改文档"。
2. **给判断，不当应声虫**：用户明确要求"你是有独立思考的 AI"——讨论时基于工程事实给推荐方案+理由+取舍，有证据时直说用户哪里不对，但用户拍板后不再纠缠（"Defer once they have decided"）。
3. **"读者自然理解"是设计验收标准**：用户判断设计好坏的试金石是"新人能不能自然而然读懂"。一个概念反复讲不清（如可见性三级反复讨论多次），说明模型本身有问题，要敢于砍概念。这轮资产模型就是这样收敛的。
4. **用户会手动改文档**：改完会告知，后续以文档现状为准对齐，不要翻旧版本说事。
5. **审查节奏**：spec 必须审过才派发（铁律）；设计文档阶段的提交节奏是"按阶段提交、提交后审"（用户已授权此节奏）；执行中出问题先停下汇报，不自作主张扩大范围。
6. **上下文成本意识**：调研类工作（如 codex-cli/pi 调研）用户会要求不浪费主会话 token——能派子 agent 的派子 agent，能先读文档的先读文档；耗时异常的任务（如 codex-cli 两小时未完成）用户会果断叫停并以结果反推选型。
7. **中文交流、中文文档**；小步快跑，不上来就搞大全套。
