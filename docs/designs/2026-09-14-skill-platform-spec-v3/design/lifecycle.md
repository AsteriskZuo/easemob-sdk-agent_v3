# 生命周期与执行

> 机制文档。术语定义见 `design/glossary.md`。业务执行模型（流程程序、SDK、agent 调用服务、子进程契约、稳定性边界）的唯一定义处是 `design/business-workflow.md`，本文只管生命周期本身的规则。

## 1. 定义

生命周期 = 业务的**一次完整执行**：任务触发创建、单次执行、进程退出即销毁。

- **平台视角一次性**：一次任务 = 一次完整执行；执行中调用几次大模型、流程几个阶段、是否流式，都是业务代码内部细节，平台不关心（见 `design/business-workflow.md` §2）；
- 无挂起/恢复机制：多轮交互的连续性由通道模块承接（见 `design/channel-model.md`），业务流程程序跨 run 无状态。

## 2. 多阶段需求的两种承接

| 路径 | 做法 | 适用 |
|------|------|------|
| **业务内多阶段** | 阶段就是流程程序里的普通代码（顺序调用、分支、循环），阶段间检查/门禁同此 | 阶段间耦合紧、数据不出业务的流程 |
| **拆业务串联** | 拆成多个业务，经内部任务队列串联：上一个业务的产出信封 = 下一个业务的入口任务，下游主动关注（见 `design/processing-chain.md`） | 阶段可独立成业务、需独立监控/复用的流程 |

**理由**：流程编排能力是业务代码天然拥有的，平台无需提供；平台保持「不认识业务内容」。

## 3. 执行隔离与稳定性

业务流程程序与 agent 调用一律在独立子进程中执行。稳定性目标与四道机械防线（子进程隔离、超时强杀、输出上限、agent 配额）的唯一定义处：`design/business-workflow.md` §6。

- **任务级 workspace 隔离**：每次执行使用独立运行目录（`businesses/{source}/{session_id}/{business_id}/runs/{run_id}/`，见 `design/console-design.md` §6）；
- **冷启动**：按需唤起有启动开销——常用程序可热池预热。

## 4. 超时

- **run 级 wall-clock 超时：默认 60 分钟**，在业务创建/配置时可修改（可选设置）；
- **通用配置与业务配置的优先级**：平台设通用配置，业务配置可与通用配置重合，**业务配置优先级更高**——超时只是第一条适用该规则的配置项，后续同类配置都按此规则。

## 5. agent 调用服务

大模型调用的唯一通道。完整契约（socket 通道、pi 子进程执行、总纲注入、skill 白名单、会话连续性、配额、审计、hooks 三条纪律）见 `design/business-workflow.md` §4；本文只保留平台侧纪律：

- **pi 是唯一内核**（决策见 `docs/decisions/2026-09-27-agent-kernel-and-execution-mode.md`）；codex-cli 不支持——hook 语义差异大、审计无法闭环，适配代价不值得；
- **模型配置是部署/业务配置而非代码耦合**；MVP 仅 **qwen3.8max**；
- 调用统一埋点：token 用量、耗时、成本上报控制台。

## 6. 资源事实

- pi 子进程**百 MB 级内存起步**，业务流程程序同样是独立进程——并发闸门据此而定，量级为几十（见 `design/scheduler.md`）；
- 响应形态：一次性或流式；流式只占一个连接，对服务是廉价 IO，不构成并发压力。
