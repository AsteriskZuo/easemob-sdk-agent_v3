# 话术集 · 关键概念定义

> 本系统（**easemob-agent**）全部关键概念的统一解释。每个概念：一句人话 + 精确义 + 要点 + 英文术语（代码实现直接使用，不再现找）。
> 维护规则：新增关键概念先进本页；概念改名/废弃只在本页改，各细节文档引用本页。

---

## 调度循环（心脏）· Scheduler Loop（Heart）

一句话：平台唯一的主循环，系统的心脏。

精确义：它只做一件事——从任务队列取出下一个任务，找到该任务的处理链，驱动业务生命周期的创建、执行、完结。心跳一次，系统前进一步；心脏停跳，全系统静止。

要点：心脏不认识业务细节——入口懂业务，信封带答案，心脏只读信封字段。

## 任务队列（主任务队列）· Task Queue

一句话：系统的统一入口缓冲带。

精确义：任何触发（外部通知、内部通知、定时到点）都先被包装成任务放进来，由调度循环按到达顺序逐个取出消化。先进先出、持久化（SQLite）。

要点：系统中其他队列（如日志队列）都是局部的、服务于特定模块的；不加前缀说「任务队列」，专指这一条。

## 业务处理链（处理链）· Processing Chain

一句话：一个任务的业务处理流水线。

精确义：任务被取出后，关注了该任务的下游业务按既定顺序组成的有序处理序列。链内串行执行；依赖的前置失败时后者是否执行，按依赖配置决定（默认不执行）；无依赖的，失败不株连。

要点：依赖关系在控制台可视化配置；上游不知道谁关注了自己，关注是下游的声明。

## 门禁 · Gate

一句话：业务在处理链上的入口检查。

精确义：回答「这个任务我该不该接」——在入口处拦截，判的是**输入就绪**（含对上游产出的验证），不只是「与我有关」；输入未就绪则跳过，不阻塞链上后续业务。

要点：门禁是业务稳定运行的基础防线，与依赖语义互为双保险。

## 会话通道（通道）· Session Channel ｜ 通道键 · Channel Key

一句话：同一个会话的任务排队用的虚拟队列。

精确义：以通道键标识的虚拟执行通道；同通道任务严格串行，不同通道自然并行。通道键 = `source__session_id`（双下划线分隔，不用冒号——避免文件路径转义问题）。

要点：通道创建即持久化到数据库（防意外丢失），完成时只做状态变更；串行/并行是通道的自然属性，不是业务的配置项；最大通道并发数可在控制台修改。

## 并发闸门 · Concurrency Semaphore

一句话：全局执行并发上限。

精确义：一道全局信号量，生命周期执行前取令牌，取不到就等。作用是保机器——每个并发执行是一个真实沙箱进程（百 MB 级内存），闸门值按部署机器资源定，控制台可修改。

## 生命周期 · Lifecycle

一句话：业务的一次完整执行。

精确义：业务组合体被任务触发后创建的动态执行实例，单次执行，跑完即销毁。包是静态的，生命周期是活的。

要点：平台不支持多阶段代码；复杂业务的多阶段需求用两种转化路径承接（见 `design/lifecycle.md`）。

## 业务标记 · Business Markers

一句话：任务状态的平台统一投影。

精确义：生命周期实例的状态机（创建/进行中/成功/失败/超时）在控制台的呈现，由平台统一打标，业务管理者无需操作。业务标记与生命周期状态是同一内容、两个视角。

## 会话 · Session

一句话：跨任务的上下文串联键。

精确义：平台侧的会话，**不等于 agent-cli 的会话**（大模型会话）——两者由会话模块维护映射。会话标识 = `source__session_id`；session_id = 业务id + 时间戳 + 随机数。

要点：四个基本操作——创建、恢复、压缩、清空（见 `design/session-model.md`）。

## 业务 · Business

一句话：一个完整可执行的自动化单元。

精确义：业务 = **提示词（总纲）+ 一组 skill（内置的/自己上传的/他人公开的）+ agent-cli + 大模型**，外加一个必选入口、一个可选出口。业务与入口机械绑定，不会错配。

要点：触发订阅事件的是业务组合体，不是单个 skill。

## Skill（包）· Skill Package

一句话：能力单元、工具单元。

精确义：遵循公开 skill 规范的静态包（SKILL.md 式），是业务的组成部分，没有更多特殊身份。不为本平台做任何适配；推荐在必选字段之外添加版本号属性。

要点：分 public（通用共享）/ private（业务专属）两种可见性，存放位置不同；平台登记元数据（整包 hash、创建/修改时间等）。

## 事件 / 任务 · Event / Task

- 事件（Event）：驱动平台的最小输入单元，由事件信封承载。
- 任务（Task）：事件包装后的可执行单元，进入任务队列等待消化。外部通知、内部通知、定时到点统一包装成任务。

## 控制台 · Console

一句话：服务系统全部控制开关与仪表盘的集合。

精确义：与服务交互的可视化入口——查看状态、监控状态、控制运行规则、增减规则。本身无业务逻辑。

## 子任务队列 · Sub-task Queue（预留概念）

一句话：执行通道的实体化形态。

精确义：按业务特点划分的实体队列，各自独立决定串行/并行。当前阶段以虚拟会话通道实现，不实体化；将来拆分执行层时可物化。
