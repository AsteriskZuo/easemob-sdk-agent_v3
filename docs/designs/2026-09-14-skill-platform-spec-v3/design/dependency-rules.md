# 依赖管理规则（四类归宿）

> 顶级工程规则，所有模块的设计与实现必须遵守。动机：装配无规则 = 主板飞线——参数透传层级一深，维护成本失控。
> 判定口诀：**「有没有第二个实例存在的场景？」**

## 1. 环境变量

**是什么**：进程级、部署期确定的配置（端口、数据目录、日志级别、超时默认值等）。

纪律：

- **唯一读取口**：`@asterisk/agent-env` 包；禁止任何模块散点读 `process.env`；
- 启动时统一解析 + 校验，缺必需项 **fail-fast**（带病运行比不运行更危险）；
- 初始化后不可变（改配置 = 重启进程）。

注意区分：业务的密钥/环境配置（控制台管理、按业务隔离、运行期变化）**不是**这里说的环境变量，那归 EnvProvider（数据库存储，属第 3 类注入对象）。

## 2. 全局共享（模块级单例外观）

**是什么**：无实例差异的横切工具——全平台到处用、不存在「两个不同实例」、行为全局一致。当前成员：平台日志外观、env 读取、id 生成、时钟。

形态：**模块级单例外观**——包内持内部实例 + 导出委托函数（`logger.info(...)` 直接可用），不用 class static（测试隔离与接口类型化都别扭）。

纪律：

- 装配根（main.ts）启动时 `init` 一次，自检在这里 fail-fast；**未初始化就调用 = 抛错**（防启动顺序隐 bug）；
- **初始化后配置不可变**——没有运行时 setLevel 式旋钮，改配置 = 重启；
- **唯一例外：只增不改（append-only）的注册表**。理由实例：日志脱敏值——业务密钥在控制台运行期创建，部署期不存在，只能运行时登记；只增不改意味着无行为分叉，不破坏不可变语义；
- 提供 `resetForTests()` 供测试隔离；
- **反例红线**：有实例差异的对象禁止全局化（入口/出口两个队列实例就是反例）。

## 3. 上下文注入（参数传递）

**是什么**：有实例差异、有生命周期、有明确所有者的对象：Database、TaskQueue ×2、Registry、ChannelPool、WorkflowRunner、AgentService 等。

纪律：

- **只允许直接使用者持有**；**禁止透传**——A 传 B 只为 B 转给 C 就是飞线，出现即说明装配分层错了，停下来改结构；
- 构造函数的服务参数超过 3 个 → 审视分层；
- 装配根统一 `new` 与连线（core-modules §2 依赖方向），**模块间不互相 new**；
- 测试经同样的公开接口注入 fake，不 mock 内部实现。

## 4. 纯函数

**是什么**：无状态计算——时间格式化、id 编码、信封校验等。普通函数，不进类、不进注入。

## 判定流程

```text
部署期确定的进程级配置？          → 环境变量（env 包）
无状态计算？                     → 纯函数
存在「第二个实例」的场景？        → 上下文注入
全平台横切、行为全局一致？        → 全局共享（模块级单例外观）
```

## 5. 外部能力选型：子进程使用标准

**是什么**：调用进程外能力（CLI 命令、外部服务）时的取舍纪律。子进程代价大——启动开销、宿主机二进制/版本依赖、stderr 文本级错误、测试需 mock 进程，**非必要不使用**。

**标准**——满足其一才允许子进程：

- **S1 隔离需求**：执行对象本身要被隔离——agent 运行时（pi/codex，含 sdk.agent 这类 pi 封装）、`workflow-runner` 运行业务流程程序（业务隔离）、`sdk.run` 执行不可控子程序。特征是「这个进程就是要被隔离的对象」；
- **S2 无进程内等效能力**：目标能力没有 API/库可进程内调用，或属于环境保证安装的经典 CLI（git 即此类——部署环境承诺提供，天然子进程）。

**不满足 S1/S2 时的优先级**：`npm 库` > `fetch 直连 REST` > `子进程`。判例：github 出口工具曾选 gh CLI（子进程），2026-10-03 调研后以 `@actions/github`（Octokit REST 客户端，npm 库）替代——token 显式注入、无宿主机状态、容器化友好。

**子进程的封装纪律**（一旦触发 S1/S2）：

- 统一 `runProcess(cmd, args, opts)` 原语（数组参数拒绝 shell 拼接、env 合并策略、超时、非零退出抛错带 stderr 截断），禁止各模块手写 spawn/execFile；
- 工具类保留注入缝（runner 接口），测试注入 fake，不起真实进程；
- 新需求优先「组合原语拼参数」而非「工具类加方法」，扩展点在调用方/适配层。
