# Skill 包模型

> 机制文档。术语定义见 `design/glossary.md`。

## 1. 定位：能力单元，没有更多

Skill 是**能力单元、工具单元**，是业务的组成部分——没有更多特殊身份。

- **触发订阅事件的是业务**（业务流程程序 + 业务资料），不是 skill；skill 不持有 triggers，入口绑定在业务上；
- skill 遵循**公开 skill 规范**（SKILL.md 式），**不为本平台做任何适配**；
- 推荐作者在规范必选字段之外添加**版本号**属性。

## 2. 可见性：public / private

上传时选择可见性，两种模式的存放位置不同（文件树见 `design/console-design.md` §工作目录）：

| 模式 | 语义 | 存放 |
|------|------|------|
| **public** | 通用共享，所有业务可选用；如 Jira 工具 skill——他人可直接使用，但需提供自己的有效账号（凭证按业务隔离）。**内置 skill 随平台仓库发布，首启登记，与用户上传的同规则** | 平台工作目录 `public/skills/` |
| **private** | 归属**创建者账号**：该账号创建的所有业务都可选用（一个账号可创建多个业务），其他账号不可见、不可使用 | 账号子目录 `accounts/{账号id}/skills/` |

**权限模型只有读 / 写两类**，没有"执行"权限——skill 由生命周期执行，业务选用后即可运行，不构成独立权限：

| 模式 | 读（查看、选用进业务） | 写（更新、删除——删除属写操作） |
|------|----------------------|-------------------------------|
| public | 所有人 | **创建者或 admin** |
| private | 创建者（admin 兜底） | **创建者或 admin** |

- **admin 兜底**：防止创建者离线、离职导致 skill 成为无人可管的死资产（与 `design/accounts.md` "admin 可干预任何业务"一致）；
- **更新 = 同名登记新版本**：整包 hash 兼任 id、内容变即 id 变（§3），所以"更新"不会打断正在用旧 hash 的业务；权限管的是"谁能往这个 skill 名下推新版本/下架它"，内容本身不可变。

## 3. 平台元数据

平台维护管理 skill，登记时在包外附加元数据（不改写包内容）：

| 元数据 | 用途 |
|--------|------|
| 整包 hash | **兼任内部编号**（短哈希形式，git 式截断展示）：天然唯一、自带完整性校验、同包同 id 天然去重、内容变即 id 变（与钉版本语义一致）——省去一个字段的维护 |
| 可见性 / 创建者（owner_id） | 读写权限判定（§2）；owner_id 即上传账号，admin 兜底 |
| 创建时间 / 修改时间 | 管理与审计 |

元数据随真实需求增补（最小设计原则）。

## 4. 工具 schema 与注入

- skill 对大模型暴露的调用描述为简式 schema（名称/参数/返回），风格与 skill 规范一致；
- 业务运行时，平台把该业务选用的 skill schema 注入 agent 上下文；**按需注入为默认**（schema 占上下文窗口，平台提供分组与检索注入）；
- **工具调用预算**：按任务设置调用次数/费用上限，防模型死循环调工具。

## 5. MCP

**不支持，后续是否支持待定，不预留接口。** 理由：各家大模型对 MCP 的支持程度与配置方式差异明显，远没有 skill 规范统一、标准。

## 6. skill 与 run 内钩子（pi extension）

skill 可附带 **pi extension**（TypeScript 模块）：agent 调用时平台经 `-e` 白名单注入，在会话内生效（输入改写、工具拦截、请求审计等）。用途定位：**会话内守卫**——需要拦会话中间态的机械保证（如脱敏拦截、LLM 请求体审计）归这里；不进会话的业务环节（检查/获取/脱敏/还原/门禁）归业务流程程序（`design/business-workflow.md` §5）。

遵守 hooks 三条纪律（fail-closed、判定自写结构化日志、`before_provider_request` 落盘审计）——唯一定义处：`design/business-workflow.md` §4。
